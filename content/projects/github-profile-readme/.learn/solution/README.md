# Create Your GitHub Profile README - Reference Solution

## Purpose

This is a guide for reviewers. The README content is up to each student, so there is no single correct README. This page lists what a passing submission must show and gives an example of a minimal valid profile README.

## What the submission looks like

The student submits one URL: `https://github.com/<username>`.

Behind that URL there must be:

- A **public** repository named exactly `<username>/<username>`.
- A `README.md` at the root of that repository, rendered at the top of the profile page.
- At least one commit in the repository history authored by the student (not only the initial commit GitHub creates), with a descriptive message.

## Review checklist

| Criterion | How to verify |
| --- | --- |
| Special repository exists and is public | Open the profile URL in an incognito window: the README appears above the pinned repositories. |
| Introduction | The README states who the student is (name or alias, plus what they do, study, or are learning). |
| Contact | At least one working link (LinkedIn, public email `mailto:`, portfolio, X, etc.). Click it. |
| Markdown renders correctly | Headings, lists, links, and images display correctly; no raw Markdown syntax or broken images. |
| Real and personal content | No placeholders (`<your name>`, `[Your Name]`, `Lorem ipsum`), no leftover template sections, no obviously made-up facts. |
| Git usage | Open `https://github.com/<username>/<username>/commits`: there is at least one student commit after the initial one, with a descriptive message (not `update`, `asdf`, `.`). |

Design, length, and number of sections are **not** evaluated.

## Main path vs. agent alternative

The manual path is recommended because the goal is to practice Markdown and Git. The agent alternative exists so students don't get stuck: they can use it for the content, for the Git commands (with the agent explaining each one), or both. A submission made with a coding agent passes under the same criteria. Watch for signs that the agent output was not reviewed:

- Generic filler phrases ("passionate developer with years of experience") from a student in prework.
- Contact links pointing to example domains or non-existent profiles.
- Badges or stats widgets for technologies the student has not used.

If you see these, ask the student to review and edit the README before approving.

## Example of a minimal valid profile README

```markdown
# Hi, I'm Ana 👋

I'm a former accountant starting my journey in AI Engineering at 4Geeks Academy.
Right now I'm learning the command line, Git, and GitHub.

## What I'm interested in

- Automating boring tasks
- Data and finance
- Building tools with AI agents

## Contact

- 💼 [LinkedIn](https://www.linkedin.com/in/ana-example)
- 📫 [ana.example@email.com](mailto:ana.example@email.com)
```
