## 🎯 Your challenge

Your GitHub profile is your business card as a developer. Recruiters, classmates, and future clients will visit it to find out who you are, what you are learning, and how to reach you. Right now it is empty, and that is your first project: **give your profile a face**.

GitHub has a special feature: if you create a **public** repository named **exactly like your username**, the `README.md` of that repository shows up at the top of your profile. That file is written in **Markdown**, and you will create, version, and publish it with **Git**, just like any other project.

The content is up to you: you decide how to introduce yourself. The only requirements are that anyone visiting your profile knows **who you are** and **how to contact you**. Beyond that, add whatever you like: what you are learning, technologies you are interested in, your hobbies, images, GIFs, badges, or stats.

## 🌱 How to start the project

This project does not use a template: you will create your own repository from scratch.

1. Sign in to [GitHub](https://github.com/) (if you don't have an account yet, create one with a professional username).
2. Create a new repository at [github.com/new](https://github.com/new) with these settings:
   - **Repository name:** exactly your username (matching upper and lower case). GitHub will show a message saying it is a special repository ✨.
   - **Visibility:** `Public`.
   - Check **Add a README file**.
3. Clone the repository to your computer from the terminal:

```bash
git clone https://github.com/<your-username>/<your-username>.git
cd <your-username>
```

From here, follow the main path in the next section.

## 💻 What you need to do

> 💡 **Why by hand?** This project exists so you can practice three things you will use every day as a developer: writing **Markdown**, saving your changes with **Git** (`add` and `commit`), and publishing them to **GitHub** (`push`). That is why we recommend the manual path: making mistakes and fixing them is part of learning.

> 🤖 **Feeling stuck?** If you don't know what to write, Markdown looks strange, or the terminal scares you, don't stop. Get help from a coding agent (explained in the alternative below). You can use it only for the part you find hard or for the whole process. What matters is that you finish and understand what was done.

### Main path: manual version (recommended)

You write the README yourself, line by line.

- [ ] Open the repository folder in your code editor (for example, VS Code).
- [ ] Edit the `README.md` file using Markdown: headings (`#`, `##`), paragraphs, lists, links (`[text](url)`), images (`![alt](url)`) and, if you like, emojis.
- [ ] Include an **introduction** (who you are, what you are learning, or what you are interested in).
- [ ] Include at least one **way to contact you** (LinkedIn, public email, portfolio, X, etc.).
- [ ] Check how it looks with your editor's Markdown preview (in VS Code: `Ctrl+Shift+V` / `Cmd+Shift+V`).
- [ ] Save your changes with Git and upload them to GitHub from the terminal:

```bash
git status
git add README.md
git commit -m "Add profile README"
git push
```

- [ ] Open `https://github.com/<your-username>` and check that the README shows up on your profile.
- [ ] If you want to improve something, edit, make a new `commit` with a descriptive message, and `push` again.

### Alternative: with help from a coding agent

Use a coding agent (Claude Code, Cursor, GitHub Copilot, Codex, or another) as support: to get ideas, to complete or improve the README you started by hand, or to guide you through the Git commands. You lead and review.

- [ ] Open the repository folder with your coding agent.
- [ ] Ask it for help with the content, giving it real information about yourself. For example:

```text
I want to create my GitHub profile README in the README.md file in this folder.
About me: <your name>, <what you do or study>, I am learning <technologies>,
I am interested in <topics>. People can reach me at <links>.
Use Markdown, a <friendly/professional> tone, and add <emojis/badges/an image> if it fits.
Do not make up any information: if something is missing, ask me.
Briefly explain the Markdown syntax you use.
```

- [ ] Read the result line by line: remove anything that isn't true, adjust the tone so it sounds like you, and verify that every link and image works.
- [ ] Ask the agent for changes as many times as you need until the README represents you.
- [ ] Publish your changes. You can do it yourself with the commands from the main path, or ask the agent to do it with you:

```text
I want to save and upload my changes to GitHub.
Before running each Git command, explain what it does and why.
Use a descriptive commit message.
```

- [ ] Open `https://github.com/<your-username>` and check that the README shows up on your profile.

> ⚠️ **IMPORTANT:** The agent is your assistant, not the author. You are responsible for every line published on your profile, and you must understand every command that was run: you will use them in all your projects. Do not share private data (address, personal phone number, ID documents), and do not leave filler text like `<your name>` or made-up information.

## ✅ What we will evaluate

- [ ] There is a **public** repository with the same name as your username, and its `README.md` is displayed on your GitHub profile.
- [ ] The README includes an **introduction** that makes it clear who you are.
- [ ] The README includes at least one **way to contact you** with a working link.
- [ ] The Markdown renders correctly: headings, lists, links, and images (if any) look right and there are no broken links.
- [ ] The content is real and personal: no filler text, unfinished templates, or made-up information.
- [ ] The repository history has at least one `commit` of yours with a descriptive message, uploaded with `git push`.

> Note: we do not evaluate the design or the number of sections. A short, clear, and honest README is worth more than a long, generic one.
